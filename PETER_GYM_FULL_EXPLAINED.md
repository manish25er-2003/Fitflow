# Peter-GYM App Explained

## 1) How many dashboards does the app have?

This app has 3 main dashboards after login:

### A. Admin Dashboard

- Role: super_admin / gym_admin
- Route: /admin/dashboard
- Purpose: full gym operations dashboard
- Visible features: members, plans, payments, training, reports, settings, notifications

### B. Trainer Dashboard

- Role: trainer
- Route: /trainer/dashboard
- Purpose: assigned members and training tracking

### C. Member Dashboard

- Role: member
- Route: /member/dashboard
- Purpose: personal fitness and membership overview

---

## 2) What happens when a new user comes to the app?

The real flow is:

1. Open the website
2. App checks if a user already exists in session
3. If no user: redirect to intro screen
4. Intro screen shows splash brand screen and countdown
5. User can click Skip Intro or Login
6. On Login, app verifies credentials
7. On Register, user chooses name, email, password and role
8. The app creates the user session and sends them to their dashboard

---

## 3) Default role when a user registers

In the code, the default selected role is always:

- Member

This is set in RegisterPage:

`const [role, setRole] = useState<Role>("member")`

So if the user does not choose another role, they are created as a Member.

Role mapping:

- Member -> /member/dashboard
- Trainer -> /trainer/dashboard
- Gym Admin / Super Admin -> /admin/dashboard

---

## 4) Registration flow in simple words

A new user does this:

1. Enters full name
2. Enters email
3. Enters password
4. Chooses role from dropdown
5. Submits form
6. App creates the user account
7. App saves the user in local storage or Firebase
8. App redirects to correct dashboard

## 8) Firebase and Firestore usage

### Firebase Authentication

The app uses:

- createUserWithEmailAndPassword
- signInWithEmailAndPassword
- signOut
- onAuthStateChanged

### Firestore

The app is designed to save users in:

`users/{uid}`

Data stored includes:

- name
- email
- role
- gymId
- avatar
- createdAt

### Important note

If Firebase env variables are present, the app uses real Firebase.
If not, it falls back to demo localStorage mode.

So the app is Firebase-ready, but not fully production-live without environment setup.

## 10) Final summary

This is a strong gym management dashboard prototype.
It already has a proper role-based system and UI for all main gym users.

But the real production backend still needs:

- live Firebase setup
- Firestore collections
- real member data management
- real attendance tracking
- real payment verification
- real notification backend

The project is already a solid frontend demo and dashboard architecture.
